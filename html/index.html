Introduction

This code samples the PPG using interrupts and saves the data in binary format. The code is designed to run the SAMD21 at 2.5V without an additional clock battery. Hardware USB detection is performed by sampling the VUSB line
and a LOW will reduce the processors speed below that which is required for normal USB operations in order to save power. Hardware SD-Card detection is performed by checking the physical card switch.
A ring buffer is used for sampling and the previously sampled half of the buffer is saved to disk whenever the read counter passes either the half-read mark or the upper bounds.

Notes

  • In order to allow for low voltage operation a modified version of the Adafruit Feather M0 bootloader is used where NVM states are set to 3 (longer delay in between FLASH read/write due to the lower power) and the Brown-out
    detection is set to 1.7V (Automatic restart at too low power detection).
  • This code demands that the SD-Card is formatted ExFat as it (seemingly) is the best option for smooth read/write SD-Card operations and uses a modified version of the SDFAT library version SDFAT ADAFRUIT FORK The library needs to have the added line '#define SDFAT_FILE_TYPE 3' in SdFatConfig.h around line ~50
  • The code uses a modified version of the RTC library in order to disable the automatic switchover from VDD to battery power, this is necessary due to the fact that a fresh clock battery will output a higher voltage than
    the internal 2.5V regulators.

Known issues

  • There is still an issue with a 2 second gap in data reads happening every once in a while, the source is still unknown.
  • Pre-allocation will not work twice even on different files unless device is restarted in between. Assuming something is up with the SD-Card or SPI still being open but simply resetting the CPU for now to overcome it.

Settings

The code uses a number of #defines to modify compile-time settings;

  • PPGDEBUGOUT - Enables serial output of the PPG data in order to do live monitoring
  • BINWRITE - If defined, saves the data in binary format (More or less required at this stage)
  • PREALLOCATE - If defined, pre-allocates a file size in order to minimize write delays (More or less required at this stage)
  • PREALLOCSIZE - Defines the pre allocated file size
  • DEBUG - Enables SD-Card data writes even when USB is connected
  • CPUDIVNOUSB - Sets the clock divider used when running in battery mode (No USB detected). Default is 6 (0.75MHz)
  • CPUDIVHIGH - Sets the clock divider used in normal USB mode. Default is 0 (48Mhz)
  • updateRate - Sets the sample rate, given in samples per second
  • secondsToSamples - Sets the size of the ring buffer, the maximum size is dependent on [/ref updateRate]. The theoretical maximum memory usage is 22K, the compiler DOES NOT RELIABLY TELL YOU if you go over this limit. Reference values are a buffer of 60 seconds for a sample rate of 45Hz, 120 seconds for 20Hz and 50 seconds for 60Hz
  • readBits - Sets the bit depth to sample at. The default is 22
  • divider - If readBits is > 16, this sets the divider used to divide down the incoming data to 16 bits. Use divider = 2^(readBits - 16), for 22 bits divider = 64

Detailed workflow

Setup:

  1. Set High CPU speed (Safeguard against dirty reboot at low CPU speed) [setCPUSpeed]
  2. Set the brown-out low voltage detection to 1.7V (Needed to run the device at 1.8V) [setBODlow]
  3. Set port input/output modes, note the use of pinPeripheral as the SAMD21 has a multitude of functions per pin.
    pinPPGVolt is purposefully left out in order to leave it in PWM mode.
  4. Set the ADC resolution to 22-Bits [analogReadResolution] (readBits)
  5. Check if USB is connected, if it is enable the USB hardware and the USB Serial device, otherwise do not.
    Leaving the USB turned off during battery operation is cruical as the device is slowed down to a speed incompatible with USB communcations, any attempt to use the USB port here can hang the processor.
  6. Initialize the RTC module over I2C and wait until a proper response is received. A hardware error with the RTC will make the device stop here.
  7. Disable the RTC battery switchover [disableRTCSwitchover] and verify it [readRTCSwitchover]
  8. Enable PPG LED and wait in order to signal restart
  9. Attempt initiation of SD-Card, a failure here will still allow execution to continue in order to receive USB commands to set the clock etc and does initiate the SPI hardware (?)
  10. Modify CPU speed in accordance to whether USB is plugged in or not [setCPUSpeedAccordingToUSB]
  11. Run another standard SD-Card check, this is necessary as it will set various flags etc. [waitForCard]
  12. Start the data read interrupt

Loop:

  1. Modify the CPU speed according to the state of the USB cable [setCPUSpeedAccordingToUSB]
  2. Check if we still have a SD-Card, if we do, continue to save data [saveData]. If we do not, and we do not have USB plugged in (Patch running on low non-USB compatible speed), make sure to turn all USB communications off.
    Run the standard SD-Card check [waitForCard]
  3. Check if USB is connected or if the [allowLoop] flag is set. If neither of these are true, jump back to the beginning of the function.
    While in battery mode we deliberately prevent the execution of the main Arduino service loop as it performs USB functions that do nothing but draw extra power while USB is not functional.
  4. If USB is indeed connected, check if there are any USB commands that need to be taken care of before executing the main Arudino service loop [readSerialCommands]
