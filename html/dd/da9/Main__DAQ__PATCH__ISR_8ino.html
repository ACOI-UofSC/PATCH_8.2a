bool waitForCard (int timeout=1000)
 Waits for a SD-Card to be inserted for [timeout] milliseconds before automatically returning. the PPG LED is turned off during the wait in order to visually indicate that an SD-Card isn't present, when a card is detected the LED is set to PPGVOut again. It then uses waitForZeroSecond to wait for an exact second transition before starting to log readings, and resets currentSecond and currentReading. The date/time is being updated and the SD-Card is tested to make sure it works. Lastly setBinFile is used to make a new file for data logging.

void timerHandler ()
 Interrupt handler for sampling sensor data, logs it into the ringbuffer and updates currentReading += 1. If currentReading is at its bound it is set to zero and currentSecond += 1. If currentSecond == (secondsToSample / 2) (i.e. at half the ringbuffer) or currentSecond == secondsToSample (i.e. at the upper bound of the buffer), set saveFlag to true and indicate which half of the buffer to save through setting saveLowRange accordingly. Resync the date/time with updateDate and set updateFlag to true.
 
void saveData ()
 Check if saveFlag is set, if not return immediately. Check if the SD controller can be started, otherwise return and clear saveFlag and set saveError Unless DEBUG is set, check if USB is connected and return if so. Set the range of data to set depending on saveLowRange. In order to maximize power efficiency, set the processor speed to max during save. Save as binary or .csv depending on compile-time flag. If binary, see if the file is already open and if not open it and pre-allocate. Write and flush but do not close file.

Not closing the file and using flush could be a bad move from a power efficiency perspective, but ExFat is very picky and doesn't seem to work right unless it is done exactly so. Pre-allocation on different files without resetting the processor does not work for unknown reasons either.
